# 背包系统

> 更新时间：2026-05-29。背包本体以数据库为权威，地图搜索区物品以 Redis loot 为权威。

## 权威数据

- 背包物品：`player_backpack_item`。
- 背包解锁：`backpack_unlock_order` 与当前玩家解锁状态。
- 地图搜索区/战斗宝箱：`tower:loot:{userId}:{runId}`。
- 地图格状态：`tower:map:{userId}:{runId}:{mapId}`。

## 移动接口

`POST /api/backpack/move`

| moveType | 必传字段 | 行为 |
| --- | --- | --- |
| `MAP_TO_BACKPACK` | `cachedItemId`、`slotIndex`、`gridRow`、`gridCol` | 从 Redis loot 放入背包 DB，成功后删除该 `cachedItemId` |
| `BACKPACK_TO_BACKPACK` | `placementId`、`slotIndex`、`gridRow`、`gridCol` | 背包 DB 内移动或叠加 |
| `BACKPACK_TO_MAP` | `placementId` | 删除背包 DB 记录，并在当前坐标创建 Redis loot |

## 搜索区流程

1. 战斗胜利时，后端创建 `mapCacheId` 写入 `tower:loot:{userId}:{runId}`。
2. Unity 发送 `ITEM_PICKUP(4001)`，body：`{ "type": 4001, "mapCacheId": "..." }`。
3. 首次打开时后端根据掉落配置 roll 出 `cachedItemId`，并写回 Redis loot。
4. Unity 将返回的 `items` 放入搜索区。
5. 玩家拖入背包时调用 `MAP_TO_BACKPACK`。
6. 后端背包 DB 写入成功后，删除 Redis loot 中对应 `cachedItemId`。
7. 如果背包写入失败，Redis loot 不删除，Unity 应保留搜索区物品。

## 地图格拾取

- 钥匙/血瓶走 `POST /api/backpack/pickupMapCell`。
- 成功后自动放入默认背包，并把对应地图格改为空地后写回 `tower:map:{userId}:{runId}:{mapId}`。
- 开门走 `POST /api/map/openDoor`，成功后消耗钥匙并把门格改为空地后写回地图缓存。

## 维护约定

- 新增任何“地图临时物品”都必须进入 `MapLootCacheService`，不要再写入 `PlayerSession/SessionState` 作为权威。
- `cachedItemId` 是 Redis loot item 的唯一操作 ID；客户端不应自行生成。
- 入包成功后才能删除 `cachedItemId`，避免“搜索区消失但背包没物品”。
