# 背包系统

> 更新时间：2026-05-26。本文描述当前后端背包权威实现，以及 Unity 搜索区/地图缓存物品的交互方式。

## 功能概览

- 每个玩家 5 个背包位：`slotIndex = 0..4`。
- 每个背包位是 10 行 × 7 列，共 70 格。
- `slot 0` 默认解锁 4×4，即 `maxUnlockedOrder = 16`。
- 物品支持 9 种占格形态，由 `item.shape_type` 决定。
- 后端负责背包放置、叠加、移动、解锁、地图缓存物品入包。
- Unity 负责展示背包格、搜索区、拖拽交互；最终结果以后端回包为准。

## 表结构

| 表 | 用途 |
| --- | --- |
| `item` | 物品配置，含 `shape_type`、`max_stack` |
| `backpack_unlock_order` | 每个 slot 的 1..70 解锁顺序与格子坐标 |
| `player_backpack_slot` | 玩家每个 slot 当前最大解锁序号 |
| `player_backpack_item` | 玩家背包内实际放置项 |

## 占格形态

| shapeType | 占格 |
| --- | --- |
| 1 | 1×1 |
| 2 | 1×2 |
| 3 | 2×1 |
| 4 | 2×2 |
| 5 | 1×3 |
| 6 | 3×1 |
| 7 | 2×3 |
| 8 | 3×2 |
| 9 | 3×3 |

对应后端枚举：`ItemShapeType`；前端辅助：`BackpackShapeHelper`。

## HTTP 接口

> 若配置了 `server.servlet.context-path: /tower`，完整路径需加 `/tower` 前缀。当前用户 ID 临时写死为 `1001L`。

### 查询背包

- `POST /api/backpack/getBackpack`
- 无请求体。
- 返回 5 个 slot，每个包含：
  - `slotIndex`
  - `maxUnlockedOrder`
  - `nextOrderNumber`
  - `nextCell`
  - `maxUnlocked`
  - `items[]`：`placementId`、`gridRow`、`gridCol`、`itemId`、`itemName`、`itemIcon`、`shapeType`、`count`

### 统一移动

- `POST /api/backpack/move`

| moveType | 必填字段 | 说明 |
| --- | --- | --- |
| `MAP_TO_BACKPACK` | `cachedItemId`、`slotIndex`、`gridRow`、`gridCol` | 地图缓存物品放入背包 |
| `BACKPACK_TO_BACKPACK` | `placementId`、`slotIndex`、`gridRow`、`gridCol` | 背包内移动或叠加 |
| `BACKPACK_TO_MAP` | `placementId` | 背包物品放回当前地图缓存 |

校验规则：

- 物品必须存在且配置了合法 `shape_type`、`max_stack`。
- 放置范围必须完全位于已解锁格子内。
- 可与同位置同物品叠加，但不能超过 `max_stack`。
- 否则不能与同 slot 其他物品占格重叠。
- `MAP_TO_BACKPACK` 成功后，后端会从 `SessionState` 地图缓存中移除对应 `cachedItemId`。

### 解锁下一格

- `POST /api/backpack/unlock`
- 请求体：`{ "slotIndex": 0 }`
- 当前只推进 `max_unlocked_order + 1`，尚未实现货币消耗。

### 拾取地图格事件

- `POST /api/backpack/pickupMapCell`
- 请求体：`{ "cellX": 1, "cellY": 2 }`
- 只处理当前地图 JSON 中的钥匙（`type=7`）与血瓶（`type=9`）。
- 玩家必须在线，且站在目标格或四邻格。
- 成功后自动放入默认背包 `slot=0`，并将地图缓存中的该格改为空地。

### 开门

- `POST /api/map/openDoor`
- 请求体：`{ "cellX": 1, "cellY": 2, "doorId": 3 }`
- 服务端校验：
  - 玩家在线；
  - 玩家与门格相邻；
  - 目标格确实是门，且事件 ID 与 `doorId` 一致；
  - 背包中存在可开该门的钥匙；
  - 成功后扣 1 把钥匙，并把门格改为空地。

## WebSocket 4001 与搜索区

`ITEM_PICKUP(4001)` 当前用于打开/查询战斗奖励缓存：

```json
{ "type": 4001, "mapCacheId": "..." }
```

成功返回：

```json
{
  "type": 4001,
  "code": 200,
  "data": {
    "mapCacheId": "...",
    "sourceType": "CHEST",
    "items": [
      { "cachedItemId": "...", "itemId": 1, "itemName": "...", "itemIcon": "...", "shapeType": 1, "count": 1 }
    ]
  }
}
```

Unity 会把 `data.items` 显示到背包搜索区；玩家拖入背包格时，再调用 `/api/backpack/move` 的 `MAP_TO_BACKPACK`。

## 前端当前注意点

- 搜索区物品不能在异步移动请求完成前销毁；成功后按 `cachedItemId` 移除，失败时保留并显示错误。
- 地图上的临时掉落必须在入包成功后再隐藏；失败时应保留，避免“地上没有、背包也没有”。
- `OpenWithChestRewards` 会先展示搜索区，再刷新背包数据；搜索区数据不应被普通背包刷新清空。
