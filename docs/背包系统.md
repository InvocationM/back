# 背包系统

本文档描述背包系统的设计、表结构、接口与使用说明。

---

## 一、功能概述

- **背包位**：每个玩家 5 个背包位（slot 0～4），第 1 个（slot 0）为默认背包位。
- **格子状态**：已解锁、待解锁、已达最大解锁上限（70 格）。
- **默认位**：网格 10 行×7 列（70 格）。序号 1～16 为已激活的 4×4 区，之后按解锁次序表逐格解锁，最大序号 70。
- **道具占格**：9 种形态（1×1、1×2、2×1、2×2、1×3、3×1、2×3、3×2、3×3），物品表配置 `shape_type`、`max_stack`；支持叠加。
- **解锁方式**：按解锁次序表顺序解锁下一格（金币解锁暂未实现）。
- **放入校验**：物品是否存在、形态合法、放置区域均在已解锁格内、不与已有放置重叠、叠加不超上限。

## 二、表结构

### 2.1 物品表 `item` 扩展

| 字段        | 类型    | 说明           |
|-------------|---------|----------------|
| shape_type  | TINYINT | 占格形态 1～9  |
| max_stack   | INT     | 最大叠加数量   |

### 2.2 背包解锁次序表 `backpack_unlock_order`

| 字段         | 类型    | 说明              |
|--------------|---------|-------------------|
| id           | INT     | 主键              |
| slot_index   | TINYINT | 背包位 0～4       |
| order_number | INT     | 解锁序号 1～70    |
| grid_row     | SMALLINT| 行 0～9           |
| grid_col     | SMALLINT| 列 0～6           |

唯一约束：`(slot_index, order_number)`。70 条数据定义 10×7 网格中每格的解锁顺序。

### 2.3 玩家背包位状态表 `player_backpack_slot`

| 字段               | 类型    | 说明                          |
|--------------------|---------|-------------------------------|
| id                 | BIGINT  | 主键                          |
| player_id          | BIGINT  | 玩家ID                        |
| slot_index         | TINYINT | 背包位 0～4                   |
| max_unlocked_order | INT     | 当前已解锁到的最大序号 1～70  |

唯一约束：`(player_id, slot_index)`。默认位（slot 0）初始为 16（4×4 已激活）。

### 2.4 玩家背包放置表 `player_backpack_item`

| 字段        | 类型    | 说明             |
|-------------|---------|------------------|
| id          | BIGINT  | 主键             |
| player_id   | BIGINT  | 玩家ID           |
| slot_index  | TINYINT | 背包位 0～4      |
| grid_row    | SMALLINT| 占格左上角行     |
| grid_col    | SMALLINT| 占格左上角列     |
| item_id     | INT     | 物品配置ID       |
| count       | INT     | 数量             |

## 四、解锁次序（10×7 网格）

- **1～16**：左上 4×4 区域（已激活）。
- **17～20**：(4,0)、(4,1)、(4,2)、(4,3)。
- **21～35**：第 4～6 列的前 5 行（行 0～4）。
- **36～70**：第 5～9 行全部 7 列，按列从上到下。

格子坐标均为 0-based（grid_row 0～9，grid_col 0～6）。初始数据见 `src/main/resources/db/data.sql`。

## 五、接口说明

> 接口基路径：`/api/backpack`。若配置 `server.servlet.context-path: /tower`，则完整路径为 `POST /tower/api/backpack/...`。当前写死用户 ID=1，无需传 playerId。

### 5.1 查询背包

- **路径**：`POST /api/backpack/getBackpack`（无入参）
- **响应**：5 个背包位的列表，每项包含：
  - `slotIndex`：背包位 0～4
  - `maxUnlockedOrder`：当前已解锁最大序号
  - `nextOrderNumber`：下一格序号（无则为 null）
  - `nextCell`：下一格坐标 `[row, col]`（无则为 null）
  - `maxUnlocked`：是否已达 70
  - `items`：该位内放置列表（含 placementId、gridRow、gridCol、itemId、itemName、itemIcon、shapeType、count）

### 5.2 统一移动（地图↔背包、背包↔背包）

- **路径**：`POST /api/backpack/move`
- **说明**：统一处理三种方向——地图缓存→背包、背包→背包、背包→地图缓存。玩家须在线（有 Session），否则返回业务异常。
- **请求体**（`BackpackMoveRequest`）：

| 字段          | 类型    | 必填 | 说明 |
|---------------|---------|------|------|
| moveType      | 枚举    | 是   | 移动类型：`MAP_TO_BACKPACK`、`BACKPACK_TO_BACKPACK`、`BACKPACK_TO_MAP` |
| cachedItemId  | String  | 条件 | 地图缓存物品 ID，`MAP_TO_BACKPACK` 时必传 |
| placementId   | Long    | 条件 | 背包放置记录 ID，`BACKPACK_TO_BACKPACK` / `BACKPACK_TO_MAP` 时必传 |
| slotIndex     | Integer | 条件 | 目标背包位 0～4，`MAP_TO_BACKPACK` / `BACKPACK_TO_BACKPACK` 时必传 |
| gridRow       | Integer | 条件 | 目标行 0～9，同上 |
| gridCol       | Integer | 条件 | 目标列 0～6，同上 |

- **成功**：code 200，无 data。
- **失败**：code 400，message 为校验错误说明（如「玩家未在线」「放置区域含未解锁格子」「与已有放置重叠」等）。

### 5.3 按序解锁

- **路径**：`POST /api/backpack/unlock`
- **说明**：将指定背包位的 `max_unlocked_order` 加 1，解锁下一格。暂不实现金币消耗。
- **请求体**（`BackpackUnlockRequest`）：
  - `slotIndex`：背包位 0～4，默认 0
- **成功**：code 200，无 data。
- **失败**：已达最大解锁（70）或参数非法时返回相应错误。

### 5.4 拾取地图物品（JSON：钥匙 type=7、血瓶 type=9）

- **路径**：`POST /api/backpack/pickupMapCell`
- **说明**：读取当前会话地图 JSON 中指定格子的首事件；若为钥匙（`type=7`）或血瓶（`type=9`），则按事件 `id` 作为物品表主键、`count` 缺省为 1，校验物品类型与事件一致（`item.type=7` 钥匙 / `item.type=9` 血瓶）后写入**默认背包位 slot=0**，按解锁序号优先叠加再寻空位锚点；成功后该格改为空地（`type=2`），并更新会话内地图与 Redis 缓存。玩家须在线且站在目标格或四邻格（曼哈顿距离 ≤1）。
- **请求体**（`BackpackPickupMapCellRequest`）：`cellX`、`cellY`（与移动协议 `targetX`/`targetY` 一致）。
- **成功**：code 200，无 data。
- **失败**：未在线、不在相邻格、非血瓶格、背包满、地图未缓存等返回业务错误信息。

## 六、放入/移动校验规则

「放入背包」由统一移动接口 `POST /api/backpack/move`（`moveType=MAP_TO_BACKPACK`）承担，以下规则同样适用于移动时的放置校验：

1. 物品存在且配置了 `shape_type`、`max_stack`，形态在 1～9。
2. 放置左上角 (gridRow, gridCol) 及形态覆盖的每一格均在「已解锁格子」集合内。
3. 若同 slot、同 (gridRow, gridCol)、同 itemId 已有放置：仅做数量合并，且合并后不超过 `max_stack`。
4. 否则：占格与同 slot 下其它放置不重叠，且 count ≤ `max_stack`。
