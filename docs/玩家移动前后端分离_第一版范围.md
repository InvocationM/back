# 玩家移动前后端分离 — 第一版范围

**第一版已按本文实现**（服务端 + 客户端）。

## 一、要做的最小闭环

### 服务端

- **Session 存位置**：`PlayerSession` 增加 `mapId`、`cellX`、`cellY`（未进图用 -1 或 null 表示）。
- **可通行校验**：根据 mapId 解析地图 JSON，实现 `isWalkable(mapId, x, y)`（type=3 阻挡不可通行，其余可通行；未在 cells 的格子默认可通行）；并校验目标格在 map 范围内。
- **查入口**：从地图 JSON 中找第一个事件 type=1 的格子，返回 (x,y)，若无则 (0,0)。
- **PlayerMoveHandler**：
  - 收到 `PLAYER_MOVE`（toX, toY；可选 mapId 用于首次移动）。
  - 若 session 尚无位置：用 mapId（或默认 1001）查入口，将 session 位置设为入口，再校验从入口到 (toX, toY) 是否相邻且可通行；通过则更新 session 为 (toX, toY)，回 200 + cellX, cellY。
  - 若 session 已有位置：校验从当前格到 (toX, toY) 相邻且可通行；通过则更新 session，回 200 + cellX, cellY；否则回 400 + message（简短原因）。

### 客户端

- **按步请求**：点击后寻路得到 path，先发 `PLAYER_MOVE`(path 下一格)；收到 **200** 后再更新 `_playerCellX/Y` 并播该格动画；到达该格后再发下一步的 `PLAYER_MOVE`，未收到 ack 前不发下一步。
- **失败**：收到 400 时清空 `_currentPath`、停止 `_moving`，可选 Toast 提示。
- **新点击直接替换目标**：移动过程中再次点击时，清空当前路径与在途请求，以当前格为起点对新目标重新寻路，只请求、只播新路径。
- **初始位置**：继续用 `FindEntrance()` 放置玩家；首次移动时由服务端用入口作当前格校验，客户端用回包同步一次位置。

### 消息约定（第一版）

- **C→S**：`{ "type": 2001, "toX": number, "toY": number }`；首次移动可带 `"mapId": number`（可选）。
- **S→C 成功**：`{ "type": 2001, "code": 200, "cellX": number, "cellY": number }`。
- **S→C 失败**：`{ "type": 2001, "code": 400, "message": "简短原因" }`。

## 二、第一版不做的（后续可加）

| 项目 | 说明 |
|------|------|
| **位置持久化** | 不往 player 表写 cell_x/cell_y；断线重连后从入口重新开始。 |
| **ENTER_FLOOR（5001）** | 不做进图协议；用方式 B（首次 PLAYER_MOVE 时服务端用入口当当前格）。 |
| **频率限制（429）** | 不限频；靠“一发一等 ack”自然降频。 |
| **stepId / 序列号** | 不防乱序；单连接下按 WebSocket 顺序处理即可。 |
| **失败回包带 currentCellX/currentCellY** | 失败只回 400 + message；不做纠偏坐标。 |
| **重连时欢迎包带权威位置** | 欢迎消息不带位置；重连视为新进图。 |
| **PLAYER_MOVE 超时重试** | 超时仅视为失败并清路径、停步；不做自动重试与幂等。 |
