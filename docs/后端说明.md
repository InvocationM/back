## 地图加载与缓存

- 接口：`POST /api/map/{mapId}`，带 context-path 时为 `POST /tower/api/map/{mapId}`。
- 优先读取 Redis：`tower:session:map:{userId}:{mapId}`。
- 未命中时查询 DB：`GameMapService.getByMapId(mapId)`。
- `GameMapService` 调用 `MapWeightSelector.applyWeightSelectionPerCell`，使每个格子的 `events` 至多保留一个事件。
- 处理后的地图 JSON 写回 Redis，移动、拾取、开门等逻辑都基于这份会话地图缓存。

## WebSocket 消息

| type | 名称 | 用途 |
| --- | --- | --- |
| `1000` | `HEARTBEAT` | 心跳 |
| `2002` | `MOVE_INTENT` | 移动与交互目标确认 |
| `3001` | `BATTLE_START` | 发起战斗 |
| `3003` | `BATTLE_RESULT` | 战斗结果 |
| `4001` | `ITEM_PICKUP` | 查询/打开地图缓存物品，常用于战斗宝箱 |
| `5010` | `BIG_MAP_USE_EXIT` | 站在出口进入下一层 |

## 移动协议：MOVE_INTENT(2002)

客户端发送：

```json
{ "type": 2002, "targetX": 4, "targetY": 5, "seqId": 12, "mapId": 1001 }
```

规则：

- 首次进图时会话无坐标，必须带 `mapId`。
- 首次进图前必须已调用 `POST /api/big-map/start`。
- `mapId` 必须等于当前章节层锁定的小地图。
- 已有坐标后，同层移动可省略 `mapId`。
- 换层必须走 `5010`。
- 目标若是交互格，`MapPathService` 会寻路到其相邻可走格，不进入事件格本身。

成功返回：

```json
{ "type": 2002, "code": 200, "status": "SUCCESS", "finalX": 3, "finalY": 5, "events": [], "seqId": 12 }
```

失败返回：

```json
{ "type": 2002, "code": 400, "success": false, "message": "无法到达目标格", "correctPos": { "x": 1, "y": 1 }, "seqId": 12 }
```

## 大章节流程

1. `POST /api/big-map/bigMapList`：获取章节列表。
2. `POST /api/big-map/start`，body：`{ "bigMapId": 1 }`。
3. 服务端为每层锁定一个小地图 ID，写入 Redis run：`tower:session:bigmap:run:{userId}`。
4. Unity 加载当前层地图并发送首个 `2002`。
5. 玩家站在出口格后，客户端先 `POST /api/map/{nextMapId}` 预加载下一层地图，再发 `5010`。
6. `5010` 成功后，服务端推进 `layerIndex`，切换会话地图与坐标到下一层入口。

## 战斗与奖励

- 客户端发 `BATTLE_START(3001)`：`monsterId`、`cellX`、`cellY`。
- 后端校验玩家与怪物格相邻、地图缓存中该格确有怪物。
- 后端计算战斗，成功回 `BATTLE_RESULT(3003)`。
- 胜利且怪物有掉落配置时，`3003.data.rewardChest` 包含 `mapCacheId` 和所在格。
- `3003` 不直接返回最终物品；首次 `ITEM_PICKUP(4001)` 才通过 `DropRollService` roll 掉落，并返回 `data.items`。

## 背包与地图缓存物品

- 查询背包：`POST /api/backpack/getBackpack`。
- 统一移动：`POST /api/backpack/move`。
- 解锁背包格：`POST /api/backpack/unlock`。
- 拾取地图格事件：`POST /api/backpack/pickupMapCell`。
- 开门：`POST /api/map/openDoor`。

`move` 支持三类：

- `MAP_TO_BACKPACK`：地图缓存物品进背包，必须传 `cachedItemId`、目标 `slot/row/col`。
- `BACKPACK_TO_BACKPACK`：背包内移动，必须传 `placementId`、目标 `slot/row/col`。
- `BACKPACK_TO_MAP`：背包放回地图缓存，必须传 `placementId`。
