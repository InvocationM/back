# 后端说明

> 更新时间：2026-05-29。本文以当前 Java 代码为准。

## 登录态

- 登录接口：`POST /tower/api/auth/login`，返回 `token/userId/username/websocketUrl`。
- HTTP 业务接口使用 `Authorization: Bearer <token>` 解析当前用户。
- WebSocket 唯一入口是登录返回的 `websocketUrl`，当前开发环境形如 `ws://localhost:8080/tower/ws?token=...`。
- `/tower/game` 已废弃，不再作为 WebSocket 客户端入口。
- v1 token 由 `AuthTokenService` 保存在内存中，服务重启后需要重新登录。

## 运行态缓存

| 缓存 | Redis key | 写入时机 | 清理时机 |
| --- | --- | --- | --- |
| 当前章节 run | `tower:run:{userId}` | `POST /api/big-map/start`，移动、换层、战斗血量变化时刷新 | 新开章节、TTL 过期 |
| 地图 JSON | `tower:map:{userId}:{runId}:{mapId}` | `POST /api/map/{mapId}` 首次加载，拾取、开门后重写 | 新开章节、换层删除上一层、TTL 过期 |
| 搜索区/战斗宝箱 | `tower:loot:{userId}:{runId}` | 战斗胜利创建 `mapCacheId`，首次 `4001` roll 并写入 `cachedItemId` | 入包成功删除 item，换层/新开章节清理 |
| 背包物品 | DB `player_backpack_item` | 拾取、搜索区入包、背包内移动 | 物品移出背包或消耗 |

缓存原则：

- Redis 是章节运行态、地图状态、搜索区物品的权威源。
- `PlayerSession` 只保留 WS 连接态和轻量镜像，不再作为地图/loot 权威。
- `MAP_TO_BACKPACK` 先写背包 DB，成功后再删除 Redis 中的 `cachedItemId`；失败不删除缓存物品。
- 所有运行态 key 带 `userId`，地图和 loot 额外带当前 `runId` 隔离。
- 运行态缓存 TTL 当前为 24 小时，每次有效读写会刷新。

## WebSocket 消息

| type | 名称 | 用途 |
| --- | --- | --- |
| `1000` | `HEARTBEAT` | 心跳 |
| `2002` | `MOVE_INTENT` | 移动与交互目标确认 |
| `3001` | `BATTLE_START` | 发起战斗 |
| `3003` | `BATTLE_RESULT` | 战斗结果 |
| `4001` | `ITEM_PICKUP` | 查询/打开 Redis loot 缓存 |
| `5010` | `BIG_MAP_USE_EXIT` | 站在出口进入下一层 |
