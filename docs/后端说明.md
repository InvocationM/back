# 后端说明

> 更新时间：2026-05-28。本文以当前 Java 代码为准。

## 登录态

- 登录接口：`POST /tower/api/auth/login`，返回 `token/userId/username/websocketUrl`。
- HTTP 业务接口使用 `Authorization: Bearer <token>` 解析当前用户。
- WebSocket 唯一入口是登录返回的 `websocketUrl`，当前开发环境形如 `ws://localhost:8080/tower/ws?token=...`。
- `/tower/game` 已废弃，不再作为 WebSocket 客户端入口。
- `BackpackController`、`MapController`、`BigMapController`、`GameWebSocketHandler` 入口层不再写死 `1001L`。
- v1 token 由 `AuthTokenService` 保存在内存中，服务重启后需要重新登录。

## WebSocket 连接规则

- `WebSocketConfig` 只注册 `/ws`，完整外部路径由 `server.servlet.context-path` 拼出，例如 `/tower/ws`。
- 登录返回的 `websocketUrl` 基于当前 HTTP 请求生成：`http/https` 转 `ws/wss`，并携带 `?token=...`。
- 不带 token 或 token 无效时，`GameWebSocketHandler` 关闭连接，不创建 `PlayerSession`。
- 连接成功后服务端发送欢迎包，包含当前 `userId/username`。

## WebSocket 消息

| type | 名称 | 用途 |
| --- | --- | --- |
| `1000` | `HEARTBEAT` | 心跳 |
| `2002` | `MOVE_INTENT` | 移动与交互目标确认 |
| `3001` | `BATTLE_START` | 发起战斗 |
| `3003` | `BATTLE_RESULT` | 战斗结果 |
| `4001` | `ITEM_PICKUP` | 查询/打开地图缓存物品，常用于战斗宝箱 |
| `5010` | `BIG_MAP_USE_EXIT` | 站在出口进入下一层 |

## 地图加载与缓存

- 地图接口：`POST /api/map/{mapId}`，带 context-path 时为 `POST /tower/api/map/{mapId}`。
- 优先读取 Redis：`tower:session:map:{userId}:{mapId}`。
- 未命中时查询 DB，并由 `MapWeightSelector` 将每个格子的 `events` 收敛为至多一个事件。
- 处理后的地图 JSON 写回 Redis，移动、拾取、开门等逻辑都基于会话地图缓存。
